# REA 功能重建 benchmark

当前版本：**v5 · 20 个原创种子 · 5 种发布形式 · 60 次模型运行**。请求模型 `deepseek-v4-flash`，服务返回 `deepseek-flash`；REA 6.4.0。目标是从发布工件恢复指定功能的可观察行为。

## Pipeline

```mermaid
flowchart LR
    A[来源与许可审查] --> B[运行和 REA 能力预检]
    B --> C[人工策划种子与功能契约]
    C --> D[原创目标与独立参考]
    D --> E[构建 clean 和 N/S/D 扰动发布物]
    E --> F[私有隐藏测试与真实依赖验收]
    F --> G[去重、多样性报告与哈希冻结]
    G --> H[相同预算上限的三组评测]
    H --> I[逐题成绩、工作流审计与实际用量]
```

N：名称/路径变化；S：实际模块分派与间接调用；D：保留无关代码/资源。扰动必须通过行为等价验收。当前是**人工策划 + 脚本构建/验收**，尚非自动生成任意应用的 agent。

## 测试结果

| 设置 | 含义 | 宏平均 | 全部隐藏输入通过 | 实际 REA 分析 | API tokens |
|---|---|---:|---:|---:|---:|
| B | 普通工具与行为查询 | 53.4% | 7/20 | 0/20 | 6,404,618 |
| REA 自选 | B + REA，由模型决定使用 | 63.5% | 10/20 | 2/20 | 6,782,705 |
| REA 工作流 | B + 初始化分析、证据阅读与行为核验要求 | 85.7% | 12/20 | 20/20* | 13,566,378 |

*工作流组的 20/20 包含控制器初始化；模型追加成功调用为 12/20，完整结构验收 7/20，兼具完整性和人工相关性要求 4/20。主分先平均题内隐藏测试家族，再平均 20 个种子；未完成工作流的候选仍计分。

工作流组相对 B 高 **32.3 个百分点**，相对 REA 自选高 **22.2 个百分点**，但实际 tokens 是自选组的 **2.00 倍**，并同时改变导航、证据记录及续行/提交规则。按技术轨聚类的“工作流−自选”95% 区间为 **[−6.2, +51.9] 个百分点**。这是分批单采样的开发集诊断，不能解释为 REA 引擎独立、稳定的净增益。
