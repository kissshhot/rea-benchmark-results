# REA 功能重建：先导实验结果

2026-10-15 · 请求模型 `deepseek-v4-flash` · REA 6.4.0 · 冻结协议 v0.2.0

在 6 个开源 JavaScript 库的 12 个功能重建任务中，REA 辅助组较直接读代码组的平均通过率高 **30.83 个百分点**。这是小规模、单次生成的描述性结果，尚不能证明稳定或可单独归因于 REA 的增益。

本仓库仅发布结果与方法概述；测试代码、用例、候选实现和原始轨迹暂不公开。

**主要结果**

| 条件 | 软件宏平均通过率 | 严格成功任务 |
|---|---:|---:|
| A：行为查询 | 53.79% | 2/12 |
| B：A + 目标代码、搜索、基础 AST 索引 | 47.50% | 4/12 |
| C：B + 显式要求 REA 分析与语义追踪 | 78.33% | 6/12 |

已知判分器问题：P12-C 的正常 `list.__len__()` 被误拦截，主表记为 0 分。仅修正该规则、保持原代码与用例不变重放后，该任务 **200/200** 通过；相应 C 组为 **86.67%**、C−B 为 **+39.17 个百分点**、严格成功 **7/12**。这是事后敏感性检查，没有新增模型调用，不替换冻结主成绩，也不构成独立重复。

**测试集与评测方式**

| 目标库（固定版本） | 功能任务 |
|---|---|
| PapaParse 5.5.3 | P01 CSV 解析；P02 CSV 导出 |
| Fuse.js 7.1.0 | P03 字符串模糊搜索；P04 字段加权搜索 |
| marked 15.0.12 | P05 行内 Markdown；P06 块级 Markdown |
| diff-match-patch 1.0.5 | P07 语义 diff；P08 模糊补丁应用 |
| semver 7.7.2 | P09 版本排序；P10 版本范围筛选 |
| minimatch 10.0.3 | P11 glob 匹配；P12 路径列表过滤 |

- 输入由预设模板与固定随机种子合成，标准答案来自原始 npm 包实际执行。每任务 5 类输入、10 条公开示例、200 条隐藏用例；公开与隐藏输入不重叠，但主要共享模板。共 2,520 条输入，原始包、压缩包和重复执行结果全部一致。
- 目标工件是无 source map 的压缩 JS 包；B、C 获得相同代码访问能力。模型用 Python 标准库重建指定接口，离线运行。范围限于选定功能，不覆盖完整应用、GUI 或原生二进制。
- 三组共享任务说明、公开示例和预算；B 必须先检查代码，C 必须先完成 REA 分析与追踪。每任务每组生成 1 次，共 36 次有效运行。每次最多 20 次模型响应、24,000 输出 token、80 条原软件查询、600 秒；温度 0.2，关闭 thinking。输入 token 未设等量配额。
- 比较输出的结构、字符串、顺序和布尔值，数值容差为 `atol=1e-7, rtol=1e-6`。先平均输入类别，再平均同软件任务，最后平均软件。严格成功要求总通过率 ≥95%，且每类 ≥90%。执行以 20 条输入为一批，非零退出或输出条数错误使该批全部失败。
- 服务返回模型标识为 `deepseek-flash`，无法独立确认其内部权重快照。

**如何解读**

- 仅 6 个选定软件、每条件 1 次生成；7,200 次隐藏输入执行不是独立模型实验。模板相似、公开库训练记忆与类别偏置限制了外推，例如 P11 全部回答 false 也可通过 70.5%。
- C 组 12/12 任务调用真实 REA 分析和语义追踪；其中 10 次命中种子节点，但这 12 次查询均未展开关系边。当前差值混合了工具证据、流程引导与代码完成度，不能单独归因于深层语义分析。
- B、C 分别有 880/2,400、400/2,400 条输入因执行或提交接口问题失败（C 包含上述 200 条误拦截）。实际 C 相对 B 的输入 token 多 21.47%、平均工作流耗时多 6.83%。
- 早期调试与可选工具试验未并入此批结果。后续需要更多结构性测试、独立重复及同等流程引导对照。代码暂未公开，当前发布材料不足以独立复现完整评测。
