# v5：20 种子三组对照

[返回首页](../../README.md) · [逐题 CSV](seed-results.csv) · [汇总 JSON](summary.json) · [用量 JSON](usage.json)

2026-10-16。冻结 20 个种子，五轨各四题；同一 REL-mixed，80 个公开和 940 个隐藏输入。B 与 REA 自选为历史 40 次，REA 工作流追加 20 次，每个种子/设置只生成一次。请求 `deepseek-v4-flash`，返回 `deepseek-flash`，无法独立确认精确权重快照。REA 6.4.0。

## 设置和判分

- **B 普通工具：** 任务说明、4 个公开例子、发布工件和行为查询；直接使用同版本 Ghidra、JADX、CIL 分析、WABT、JS 阅读/搜索等工具。
- **REA 自选：** B 的全部能力加 REA，模型自主决定调用。20 次中只有 2 次使用 REA，不剔除未调用者。
- **REA 工作流：** B 加计入预算的控制器初始化分析，要求后续相关语义/依赖分析、阅读证据、新输入行为查询、实现映射和记录。该设置还改变导航、证据提交与截断/文字响应后的续行规则。

相同上限：24 次响应、20,000 个累计输出 tokens（单次 6,144）、96 次工具、16 次分析、32 个目标输入查询、12 次公开测试执行、900 秒新请求发起窗口；已开始的操作允许完成。temperature=0.2，thinking disabled。没有独立输入 token 硬上限。

模型提交独立 Python 3.9 标准库 JSONL 实现，不能代理运行目标。主分先对题内隐藏测试家族的准确率等权平均，再平均种子；严格成功要求该种子全部隐藏输入通过。微平均是全部 940 个隐藏输入的通过率。无提交、预算耗尽或流程未完成均保留在主结果中。

结构验收核对引用原文、已读字段、实现函数及查询身份，不证明模型理解正确。人工审查分布：4 题完整且相关、10 题完成相关的部分流程、1 题仅语义分析、2 题受控制器故障影响、3 题引用弱或解释错误。工作流组提交证据 65 次，其中 58 次报错；记录负担和工具可用性也是结果的一部分。

`wasm_atlas` 与 `plugin_table` 受空图处理缺陷影响；主表保留原分数。排除这两题仅作敏感性分析，工作流−B +30.6、工作流−自选 +19.1 个百分点。单独修复补测两题后，atlas 100%→100%，table 88.9%→83.3%；两题结构流程均完成，但相关性仍弱。补测不覆盖主分，也不构成独立重复或修复的纯效应。

## 用量和失败成本

正式三组共 **26,753,701 tokens**。工作流组实际总 tokens 为自选组的 **2.00 倍**；输入 13,315,305、输出 251,073，其中缓存输入 12,624,000 已包含在输入内。三组响应数分别为 374、359、441；运行耗时中位数约 129.4、127.4、153.9 秒。

工作流正式版前中止的 r2 诊断已知 1,806,456 tokens，另有 2 个响应未保存用量；修复补测另用 1,040,756 tokens。正式三组加这些诊断/补测，已知 **29,600,913 tokens**，另加未知部分。此数不包含其他历史实验或 Codex 的合成开销；不推算账户扣减或货币费用。本次整理发布没有新增 DeepSeek 调用。

## 如何解读

工作流组合设置在本批样本上分数更高，且有明显技术轨差异；这不等于验证了 REA 引擎的独立净增益。混杂包括不同批次、单采样、导航与证据要求、续行/提交规则以及不同实际 token 消耗。后续应为 B 匹配流程支持及续行协议，增加实际成本匹配、重复采样和新谱系封存集。

旧 v0.2 的 12 题报告与本版的任务、分母和严格成功定义不同，不能直接拼接或解释为同一测试集上的性能提升。[冻结来源指纹](provenance.json)用于标识私有记录；隐藏测试尚未公开，因此不构成端到端公开复现证明。
