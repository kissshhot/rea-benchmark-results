# 任务构建过程与实际用例

本说明对应 2026-10-15 发布的 REA 功能重建先导实验，主实验协议为 v0.2.0。[返回结果首页](../README.md)。论文式技术报告：[中文 PDF](../reports/tech-report-zh.pdf) / [English PDF](../reports/tech-report-en.pdf)。

功能和标准答案来自固定版本的真实开源库；任务划分与输入模板由我们设计。本轮没有直接采用上游仓库的单元测试，也不是 REA 作者发布的现成 benchmark。

本文公开 6 条评测时已提供给模型的示例。这里的“公开示例”指模型在评测中可以看到的示例；完整测试集、隐藏用例、生成器、评测代码、候选实现和原始轨迹仍不公开。输入与标准输出是数据展示，不包含测试实现。

## 1. 从开源功能到重建任务

首轮范围限定为可以离线调用、输入输出明确、便于自动判分的 JavaScript 库功能。固定安装指定版本的 npm 包，每个库选两个功能接口。库名和版本均告知模型。

| 库与固定版本 | 任务 | 输入 → 要复现的输出 |
|---|---|---|
| PapaParse 5.5.3 | P01 CSV 解析 | CSV 文本与选项 → 数据和指定错误字段 |
| PapaParse 5.5.3 | P02 CSV 导出 | 数组或对象数据与选项 → 精确 CSV 字符串 |
| Fuse.js 7.1.0 | P03 字符串模糊搜索 | 字符串列表、查询与选项 → 排名、分数、匹配位置 |
| Fuse.js 7.1.0 | P04 字段加权搜索 | 记录、字段权重与查询 → 记录 ID、排名、分数、匹配位置 |
| marked 15.0.12 | P05 行内 Markdown | 文本与选项 → 精确 HTML 字符串 |
| marked 15.0.12 | P06 块级 Markdown | 文本与选项 → 精确 HTML 字符串 |
| diff-match-patch 1.0.5 | P07 语义 diff | 两段文本 → 语义清理后的有序编辑片段 |
| diff-match-patch 1.0.5 | P08 模糊补丁应用 | 补丁文本与待修改文本 → 修改结果、每段应用标记 |
| semver 7.7.2 | P09 版本排序 | 合法版本列表、排序方向 → 稳定排序结果 |
| semver 7.7.2 | P10 版本范围筛选 | 版本列表、范围与选项 → 满足范围的版本列表 |
| minimatch 10.0.3 | P11 路径匹配 | POSIX 路径、glob 与选项 → 布尔值 |
| minimatch 10.0.3 | P12 路径列表过滤 | 路径列表、glob 与选项 → 保留顺序和重复项的列表 |

**任务与用例是不同层次。** 一个任务要求模型提交一个 Python 程序，用标准库实现指定 JSON 输入输出接口。该程序接受不同输入，接受同一任务的 200 条隐藏用例检查。三组各生成一次，所以是 12 × 3 = 36 次模型工作流，不是每条输入都重新生成程序。

接口范围预先限定。例如：P01 的错误只保留存在的 `type`、`code`、`row`；P07 使用确定性设置并要求精确编辑分段，字符串限定为 BMP Unicode；P09/P10 使用合法严格语义版本，P09 保留相等版本的输入顺序；P11/P12 使用 POSIX 路径。这些任务不要求完整兼容整个库，也不涵盖 GUI、原生二进制或完整应用重建。

## 2. 输入如何合成

每个任务预设五类行为模板，再用固定随机种子变化文本、数字、选项和排列顺序。随机文本通常是无业务含义的字母串；结构和边界来自模板，而不是任意随机拼接。

| 任务 | 五类输入模板 |
|---|---|
| P01 | 引号字段；表头与不齐行；动态类型；空行；畸形引号 |
| P02 | 分隔符；多行与引号；对象表头；标量类型；空单元格 |
| P03 | 精确匹配与并列；编辑差异；位置；阈值；大小写与最短匹配 |
| P04 | title 权重；tag 权重；位置；阈值；大小写与并列 |
| P05 | 强调与转义；代码片段；链接与图片；自动链接与 HTML；换行与删除线 |
| P06 | 标题与段落；列表；引用；代码围栏；表格 |
| P07 | 相同/插入/删除；替换；重复；词边界；BMP Unicode |
| P08 | 精确上下文；位置偏移；近似上下文；无关上下文；重复上下文 |
| P09 | 正式版；预发布；数字标识符；构建元数据并列；降序 |
| P10 | 比较符；caret 范围；tilde 与通配；hyphen 与或；预发布 |
| P11 | 星号；globstar 与点文件；花括号与字符类；extglob；否定与选项 |
| P12 | 星号与重复项；globstar 与点文件；花括号与字符类；extglob；nonull 与否定 |

以 P01 为例：先构造包含分隔符、双引号或换行的字段，再生成相应 CSV；另外构造缺少字段、多出字段、空行和不闭合引号等输入。P08 则先生成一对原文和修改后文本，调用原库创建补丁，再改变待应用文本的位置或上下文；模型实际收到的是补丁文本和待修改文本。

| 划分 | 每类 | 每任务（5 类） | 全部 12 个任务 |
|---|---:|---:|---:|
| 评测时提供给模型的示例 | 2 | 10 | 120 |
| 隐藏评分用例 | 40 | 200 | 2,400 |
| 合计 | 42 | 210 | 2,520 |

两部分使用不同固定种子，排除重复输入。它们主要共享模板，因此检验的是模板内的内容和参数变化；200 条隐藏用例不等于 200 种独立行为，也不代表未知结构上的泛化。本文只展示下列 6 条已有示例，没有新生成或替换评分用例。

## 3. 标准答案与目标工件

每条输入直接交给固定版本的原始 npm 包执行，经过预先定义的输出字段整理后保存为标准答案。没有用语言模型生成答案或充当裁判。

原库还通过 esbuild 0.25.10 打包压缩，去掉 source map；可读文本由同一压缩结果重新格式化，并提取基础函数索引。B、C 两组获得相同的代码阅读能力，C 组另外使用 REA。目标包约 19–39 KB，属于较小的 JS 工件。

原始包、压缩包和重复执行结果经过逐例对照，2,520 条均一致。这验证了本数据上的工件行为一致性与确定性，不等于验证了软件全部行为或测试覆盖完整性。数据指纹保留在 [summary.json](../summary.json)。

## 4. 实验设置的含义与比较

A、B、C 使用同一基础模型，差别在可访问的信息、工具和必需步骤；不是三种不同模型。三组都知道库名、版本、任务契约和 10 条示例，都可以查询原软件、分段写入和修改候选代码，并运行公开测试。

| 设置 | 能看到或使用什么 | 必需步骤与含义 |
|---|---|---|
| A：行为查询 | 自选输入，获得原软件输出；没有目标代码或 REA 工具 | 依靠行为证据与模型已有知识重建，不代表完全排除了训练记忆 |
| B：直接代码检查 | A + 压缩代码、由同一代码格式化的视图、文本搜索、基础 AST 函数索引 | 写代码前须读取目标或函数索引；基础索引只列名称、位置和参数，不等于 REA 语义分析 |
| C：REA 辅助检查 | B 的全部代码访问权限 + 实际 REA 6.4.0 的结构化分析与追踪证据 | 写代码前必须先分析，再追踪相关 API/属性；工具返回可能是部分证据、未命中或未知 |

| 对比 | 本轮差值 | 能说明什么 |
|---|---:|---|
| C−B（主要） | +30.83 个百分点 | 在直接代码基线上加入 REA 证据与显式分析流程后的工作流变化；未单独隔离两者 |
| B−A | −6.29 个百分点 | 增加代码访问及检查要求后的变化；本轮较多运行/提交失败，不能推断读代码普遍有害 |
| C−A | +24.54 个百分点 | 组合工作流相对行为查询的变化，不能全部归因于 REA |

实际输入示例见 [三组 prompt 原文摘录](experimental-prompts.md)：使用同一个 P01 任务对照共同正文、条件附加指令与工具权限。完整测试集仍不公开。

### 4.1 共享预算与实际成本

| 设置项 | 取值与含义 |
|---|---|
| 模型 | 请求 deepseek-v4-flash，返回 deepseek-flash；无法独立确认内部权重快照 |
| 采样 | temperature=0.2，thinking=disabled |
| 模型响应 | 最多 20 次；不是最多 20 次工具调用 |
| 输出 token | 每次最多 6,144，整个工作流最多 24,000 |
| 原软件查询 | 最多 80 条自行选择的输入，按输入条数计数；公开示例可另行运行 |
| 时间 | 600 秒后不再发起请求，允许在途请求完成；REA 调用计入同一预算 |
| 实现与执行 | Python 标准库、JSONL、离线隔离；三组使用相同写入、修改和公开测试能力 |
| 重复 | 每任务每组仅生成一次；隐藏测试不反馈给模型 |

相同上限不等于相同实际成本，输入 token 未设等量配额。C 比 B 的输入 token 多 21.47%，平均工作流时间多 6.83%。C 组 12/12 任务完成真实分析与追踪，但这 12 次查询均未展开关系边；实际工具采用不等于已经证明深层语义分析有效。

### 4.2 判分与分析单位

候选程序不能在隐藏运行期间读取原软件或参考答案。JSON 结构、字符串、数组顺序和布尔值须一致；数值使用 `atol=1e-7, rtol=1e-6` 容差。先平均每任务五类，再平均同软件两个任务，最后平均六个软件。严格成功要求总体 ≥95%，且每类 ≥90%。每批执行 20 条输入；非零退出或输出条数错误使该批全部失败。

7,200 次隐藏执行复用了同一套 2,400 条输入及 36 份候选程序，不能当成独立模型试验。完整图注、失败与资源分析以及单独的判分器敏感性检查见中英文技术报告。

## 5. 六个实际用例

以下 `input` 与 `expected` 均直接提取自冻结评测数据，保留原始用例编号与内容。JSON 中的 `\n`、`\r` 和 `\t` 分别表示换行、回车和制表符。展示顺序按目标库排列；这些例子用于解释检查点，不代表每一类用例的难度分布。

### 5.1 CSV 解析：引号、分隔符与末尾空行

用例：`P01-public-001`；输入类别：`quoted_fields`。

```json
{
  "input": {
    "csv": "gfgdqy,\"a,ppvlth\",\"a\"\"b\"\n\"line\nppvlth\",,4\n",
    "options": {
      "delimiter": ",",
      "header": false,
      "dynamicTyping": false,
      "skipEmptyLines": false
    }
  },
  "expected": {
    "data": [
      [
        "gfgdqy",
        "a,ppvlth",
        "a\"b"
      ],
      [
        "line\nppvlth",
        "",
        "4"
      ],
      [
        ""
      ]
    ],
    "errors": []
  }
}
```

引号内的逗号不能分列，两个双引号要还原成一个，引号内换行要留在字段中。未开启类型转换，所以数字 4 保留为字符串；`skipEmptyLines=false` 使结尾空行产生额外的 `[""]`。简单按逗号和换行切分会失败。

### 5.2 模糊搜索：大小写、位置与分数

用例：`P03-public-008`；输入类别：`case_and_minmatch`。

```json
{
  "input": {
    "items": [
      "gkenlr",
      "cbvkf",
      "TCBVKF",
      "tcbvkf",
      "prefix tcbvkf",
      "tcbvkf",
      "txbvkf",
      "gkenlr tcbvkf"
    ],
    "query": "TCBVK",
    "options": {
      "threshold": 0.6,
      "distance": 100,
      "location": 0,
      "isCaseSensitive": true,
      "minMatchCharLength": 2
    }
  },
  "expected": [
    {
      "item": "TCBVKF",
      "refIndex": 2,
      "matches": [
        {
          "indices": [
            [
              0,
              4
            ]
          ],
          "value": "TCBVKF"
        }
      ],
      "score": 0.001
    }
  ]
}
```

启用了大小写敏感，最终只返回大写项。除字符串外，还必须复现原列表下标 `refIndex=2`、匹配区间 `[0,4]` 以及原库分数 `0.001`。只实现包含查询词或只返回正确项目，均不满足输出契约。

### 5.3 Markdown：链接标题与图片属性

用例：`P05-public-004`；输入类别：`links_images`。

```json
{
  "input": {
    "text": "[yncxie](https://x.test/sqbaak \"3\") ![sqbaak](/img.png)",
    "options": {
      "gfm": false,
      "breaks": true
    }
  },
  "expected": "<a href=\"https://x.test/sqbaak\" title=\"3\">yncxie</a> <img src=\"/img.png\" alt=\"sqbaak\">"
}
```

检查行内链接的 href、title，以及图片的 src、alt。输出必须是原库的 HTML 字符串；额外添加段落标签、遗漏属性或改变字符串格式都可能失败。JSON 中的反斜杠只是字符串转义，不是实际 HTML 的组成部分。

### 5.4 文本差异：精确编辑分段

用例：`P07-public-002`；输入类别：`substitution`。

```json
{
  "input": {
    "a": "pcknmk cat tvkhfo",
    "b": "pcknmk cut tvkhfo"
  },
  "expected": [
    [
      0,
      "pcknmk c"
    ],
    [
      -1,
      "a"
    ],
    [
      1,
      "u"
    ],
    [
      0,
      "t tvkhfo"
    ]
  ]
}
```

`0` 表示相同片段，`-1` 表示删除，`1` 表示插入。该例把 cat 中的 a 替换为 u。需要复现原库语义清理后的分段；另一种能够完成相同文本变换的编辑序列，也可能不符合本任务的标准答案。

### 5.5 版本排序：预发布数字标识符

用例：`P09-public-004`；输入类别：`numeric_identifiers`。

```json
{
  "input": {
    "versions": [
      "1.4.5-10",
      "1.4.5-alpha.2",
      "1.4.5-a",
      "1.4.5-alpha.10",
      "1.4.5-2"
    ],
    "descending": false
  },
  "expected": [
    "1.4.5-2",
    "1.4.5-10",
    "1.4.5-a",
    "1.4.5-alpha.2",
    "1.4.5-alpha.10"
  ]
}
```

预发布部分中的数字按数值比较，所以 2 在 10 前、alpha.2 在 alpha.10 前；还需要处理数字标识符与文本标识符的相对次序。普通字符串排序不能完整复现这里的行为。

### 5.6 路径过滤：隐藏路径、大小写与重复项

用例：`P12-public-002`；输入类别：`globstar_dot`。

```json
{
  "input": {
    "paths": [
      "lsuhel.js",
      "lsuhel.ts",
      "lsuhel.txt",
      ".hidden.js",
      "src/lsuhel.js",
      "src/.dot/a.js",
      "a/lsuhel/b",
      "foo.js",
      "bar.js",
      "test.js",
      "ab",
      "lib/lsuhel",
      "a.txt",
      "mejspl.JS",
      "lsuhel.js"
    ],
    "pattern": "**/*.js",
    "options": {
      "dot": true,
      "nocase": true,
      "matchBase": false,
      "nonull": true
    }
  },
  "expected": [
    "lsuhel.js",
    ".hidden.js",
    "src/lsuhel.js",
    "src/.dot/a.js",
    "foo.js",
    "bar.js",
    "test.js",
    "mejspl.JS",
    "lsuhel.js"
  ]
}
```

`**/*.js` 匹配不同目录深度；`dot=true` 允许隐藏路径，`nocase=true` 允许大写扩展名。输出必须保留输入顺序和重复项，因此 lsuhel.js 出现两次。

## 6. 结果解释边界

- **有限接口与共享模板。** 选题覆盖 6 个小型公开 JS 库，且模型知道名称和版本，不能排除训练记忆。公共示例暴露了各类主要结构；当前结果不能直接外推到完整软件或陌生结构。
- **分布与运行失败影响成绩。** P11 全部回答 false 也能通过 70.5%，说明存在多数类偏置。冻结主结果中，B、C 分别有 880/2,400、400/2,400 条输入因执行或提交接口问题失败；C 包含下述 200 条判分器误拦截。
- **调用成功不等于深层分析有效。** C 组 12/12 任务调用真实 REA 分析和语义追踪，其中 10 次命中种子节点，但这 12 次查询均未展开关系边。工具信息与流程引导的作用尚未拆开。C 相对 B 的输入 token 多 21.47%，平均工作流耗时多 6.83%。
- **已知判分器误拦截单独报告。** P12-C 的正常 `list.__len__()` 被过宽规则拒绝，主表为 0 分。只放行该调用，保持候选代码、200 条隐藏用例和执行限制不变重放后为 200/200；对应 C 平均 86.67%、C−B 为 +39.17 个百分点，严格成功 7/12。冻结主结果仍为 C 78.33%、C−B +30.83 个百分点、严格成功 6/12。重放没有调用模型，不替换主成绩，也不是新增独立重复。
- **发布与复现范围。** 本文只增加方法说明与 6 条已有示例。完整测试集及代码暂不公开，所以公开材料不足以独立复现全流程。早期调试与可选工具试验未并入此批结果。

后续需要加入公开示例未覆盖的结构组合、真实缺陷回归案例、更多跨模块任务、多次独立生成，以及相同强度的流程引导对照。当前只报告先导趋势，不提供显著性或稳定性结论。
